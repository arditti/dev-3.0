Short: Remote access behind any tunnel

Bring-your-own-tunnel for every tunnel dev3 starts (ngrok-style providers alongside the built-in Cloudflare quick tunnel): a custom command configured in Settings → System serves the remote-access URL and per-task exposed ports alike, and the remote-access origin check now also accepts an Origin matching X-Forwarded-Host, so Host-rewriting tunnel proxies no longer break browser auth and WebSocket upgrades. A custom tunnel's edge readiness and ongoing health are verified by probing the public URL it prints, rather than trusting that a live process means a live tunnel, and a provider that hands out the same hostname twice in a row is remembered as stable, which lets a self-update stop and respawn its tunnel instead of leaking the process across the restart.
